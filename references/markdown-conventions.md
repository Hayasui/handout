# 渲染器认哪些写法

渲染器不是完整的 markdown 实现，只认下面这套子集。超出这个范围的东西要么被当成普通段落，
要么被忽略——**不要用自定义标记**，需要特殊版式就在栏名上想办法。

## 标题

`#` 一级标题（居中、蓝色，只用于文档名）。`##` 二级标题，除第一处外**每处起新页**，也是
整份文档的分页锚点。`###`、`####`、`#####` 依次是节、题、子问三级。

渲染器记住**最近一个三级标题**，用来判断当前处在哪一节——手写横线的条数例外就挂在它上面。

## 双语行

提问话术这类要念的话，写成引用块里的一对：

```
> **EN**　Hi, and thanks for making time today.
>
> **中文**　你好，谢谢你今天抽时间参加。
```

英文在上、中文在下（灰字小一号）。一个引用块里可以放多组，中间用一行裸 `>` 隔开。
`**EN**` 后面用一个全角空格接正文，也可以用普通空格。

列表里的双语行写成 `- **EN** …` 与 `- **中文** …` 相邻两行，渲染成一条带圆点的双语项。
只写 `- 中文` 的就是一条中文条目。

## 栏名

单独一行、整行只有 `**栏名**` 的，渲染成一个字段小标题。真正管用的是四个栏名，它们决定版式：

`**观察记录点**` 之后的内容渲染完，自动补手写横线，默认 4 条。某一节要是需要别的条数，
用 `--lines-rule`（或配置里的 `lines_rules`）指定，比如试玩那节给 8 条。

`**记录清单（主持人用）**：…` 与 `**提示清单（主持人用）**：…` 写在正文里，冒号后可以接一句
说明，往下直到下一个标题或字段行之间的段落、列表、表格全部进浅红框。表格在框里照常渲染。

引用块形式的是另外两个，走 `> **栏名**：…`：`> **内部提醒**：…` 与
`> **内部参考词库**（不念给玩家）：…`。后者括号里的字会并进栏名显示。

匹配栏名时整名优先，匹配不上再剥掉尾部的括号，所以「记录清单」与「记录清单（主持人用）」
都能命中同一个栏名。要增删红框栏名，改配置里的 `quote_labels` 与 `box_labels`，或直接改
脚本顶部的 `DEFAULT_QUOTE_LABELS` / `DEFAULT_BOX_LABELS`。

## 别的元素

`| … |` 表格，首行当表头加底色。`<!-- … -->` 注释整段丢掉。空行不切断区块——同一段话中间
空一行仍然是两段，但引用块里的裸 `>` 才是段分隔。

整段被全角括号包起来（`（…）`）的，渲染成灰色斜体的舞台提示，用来说明这一步在做什么。

## 已经废掉的两个标记

`[[lines:N]]` 与 `> [!WARNING]` 都不再写进 markdown。前者渲染器还认（老稿子还能渲），
后者早就不认了。横线与红框一律由栏名触发，源文件保持成干净的标准 markdown。
